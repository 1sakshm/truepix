One pixel, five steps

1. Predict

Four least-squares predictors and eleven simple ones guess the next value from pixels already decoded. An adaptive blend combines them.

2. Correct

Bias cancelling tracks the errors made in similar places and removes the part that keeps repeating.

3. Model

21 contexts estimate each bit, including exact colour differences that can learn a colour grid with no formula. Seven logistic models add their own estimates.

4. Mix

50 inputs feed five small neural mixers. A final mixer weighs those, then two adaptive maps refine the probability.

5. Code

A 32-bit binary arithmetic coder narrows an interval with every decision and writes out bytes. The decoder repeats all of this to get the pixel back exactly.

What Kodak was hiding

A strange gap

A slow general compressor, paq8px, beat image codecs by a surprising margin on the famous Kodak test set. About 90% of that gap was colour.

Photo CD

Kodak's images came from Photo CD, so their RGB values sit on a stretched integer grid, recovered here from pixels alone.

The payoff

Only 12.8% of all RGB colours can occur on that grid, and they hold 87.3% of Kodak's pixels. Exact-difference contexts turned the finding into a gain on ordinary photos too. Truepix was tuned on Kodak, so its 5.723 bits per pixel there isn't a fair score.

Try it on your own image

This is the real codec, compiled to WebAssembly, and it writes the same files as the desktop build. Drop an image to compress it and check the result, or drop a Truepix file to rebuild the original.

Drop an image or a .tpix file
PNG, JPEG, WebP or BMP, up to 16 megapixels. JPEGs come back byte for byte. Allow about 30 seconds per megapixel on an 8-core laptop, and less for JPEGs.

Reproducible floating point

245 checks. 245 exact.

Encoder and decoder must agree on every bit of floating-point maths. Each square is one build decoding another build's file. Files were byte-identical across all seven: GCC AVX2, GCC FMA, GCC SSE2, GCC -O0, Clang x64, Clang x86, WebAssembly.

What it doesn't do

  • Beat paq8px On the tuning crops, paq8px was about 5% smaller on green and 7% smaller on colour. On JPEGs it saved 26.41% against Truepix's 21.84%. It is also far slower.
  • Keep metadata For PNG and similar files, colour profiles and other metadata are not stored. JPEGs keep everything.
  • Go past 8 bits Grey or RGB, with or without alpha. Anything else is refused.
  • Rebuild every JPEG Arithmetic-coded or cut-off JPEGs can't come back exactly, so those store pixels instead, and the tool says so.
  • Open instantly A 3-megapixel PNG takes about 7 seconds to decode on an 8-core laptop, so pixel files suit archives, not web pages. JPEGs decode in about a second.
  • Run on ARM yet It compiles for ARM64 but has never been run there.
  • Claim outside proof The results have not been independently replicated.
  • Promise a stable format The file format may change. Keep your originals for now.

Use it

Truepix is a C++ codec with a small Python command-line tool. The source isn't public yet.

g++ -std=c++17 -O3 -mavx2 -ffp-contract=off -static truepix-core.cpp -o truepix-core.exe

uv run truepix compress photo.png --verify   # writes photo.tpix
uv run truepix decompress photo.tpix         # writes photo.png
uv run truepix compress photo.jpg            # the JPEG comes back byte for byte
